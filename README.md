# WorkPilot

WorkPilot is an AI automation platform MVP for small Australian service businesses. It helps teams manage customers, jobs, quotes, invoices, simulated booking confirmations and review requests, automation activity, and AI-style workflow suggestions.

Project location on this machine:

```bash

```

## Current MVP

- FastAPI backend with JWT-style bearer authentication
- Business-scoped owner accounts
- Customer CRUD
- Job CRUD with simulated automation events
- Quote CRUD with pending quote dashboard counts
- Invoice CRUD with overdue dashboard counts
- Quote follow-up automation runner
- Scheduled automation worker for appointment reminders, overdue invoice reminders, and quote follow-ups
- Dashboard metrics and estimated admin time saved
- Default automation rules and message templates
- React + TypeScript frontend with a Stitch-inspired landing page and operational dashboard
- Alembic migrations for production database setup
- Render Blueprint and Docker Compose paths for deployment-oriented environments

## Run Locally

From the project root:

```bash
make setup
```

Start the backend in one terminal:

```bash
make backend
```

Start the frontend in another terminal:

```bash
make frontend
```

Open `http://127.0.0.1:5174/`.

Useful checks:

```bash
make test
make build
make worker-once
make migrate
```

The default local SQLite database is always stored at the project root as `workpilot.db`, regardless of whether commands are launched from the root or `backend/`.

`make worker-once` runs the scheduled automation worker once. In production this is designed to run from a cron service every 30 minutes.

## Manual Commands

Backend:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
backend/.venv/bin/alembic upgrade head
backend/.venv/bin/uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

Frontend:

```bash
cd frontend

```

Docker:


```bash
backend/.venv/bin/alembic upgrade head
```

## Deploy To Render

The repository includes `render.yaml` for a first MVP deployment:

- `workpilot-api`: FastAPI web service
- `workpilot-web`: static Vite frontend
- `workpilot-db`: managed PostgreSQL database

The repo also includes `.python-version` to pin Render's Python runtime to 3.12 for backend dependency compatibility.

Deploy steps:

1. Push the latest `main` branch to GitHub.
2. In Render, create a new Blueprint from `haodonguyen/work-pilot`.
3. Set `VITE_API_URL` on `workpilot-web` to the deployed API URL, for example `https://workpilot-api.onrender.com`.
4. Set `CORS_ORIGINS` on `workpilot-api` to the deployed frontend URL, for example `https://workpilot-web.onrender.com`.
5. Leave `ALLOW_SIGNUPS=true` for open test registration, or set `SIGNUP_INVITE_CODE` to require a launch code.
6. Let Render provision the database, run `alembic upgrade head`, and start the services.
7. Open the API `/health` endpoint and the frontend URL.

Optional automation worker:

Render does not offer a free cron plan. For a paid automation runner, add a Render Cron Job that uses the same repository and database, runs every 30 minutes, and executes:

```bash
PYTHONPATH=backend python -m app.worker
```

Production env vars:

```bash
DATABASE_URL=postgresql://...
JWT_SECRET=<generated by Render>
JWT_ISSUER=workpilot-api
CORS_ORIGINS=https://your-frontend.onrender.com
ALLOW_SIGNUPS=true
SIGNUP_INVITE_CODE=<optional-private-launch-code>
VITE_API_URL=https://your-api.onrender.com
```

Before every MVP release:

```bash
make test
make build
make worker-once
```
